# تقرير تنفيذ المرحلة الثانية — لوحة إدارة النظام

التاريخ: 6 سبتمبر 2026

## النتيجة

تم تحويل المسار الحالي `adminDashboard` إلى لوحة مستقلة لإدارة النظام على مستوى المنصة، مع إبقاء لوحة المجلس منفصلة ومقيدة بسياق المجلس المختار. لم يُنشأ مسار مكرر، ولم تُجرَ أي عملية نشر أو ترحيل بيانات أو تعديل لبيانات الإنتاج.

## الوضع السابق

كانت شاشة `admin_dashboard.dart` تجمع وظائف المنصة ووظائف المجلس في مكان واحد، وتقرأ سياق المجلس الحالي وتسمح بالدخول اعتمادًا على صلاحية الإدارة المحلية العامة. لذلك لم يكن الفصل بين إدارة النظام وإدارة مجلس بعينه واضحًا.

## ما تم تنفيذه

- قصر لوحة إدارة النظام على `isSystemOwner`، وهو منعكس من سجل `platform_admins` الموثوق، وليس من دور عضوية محلي.
- إزالة اعتماد واجهة لوحة النظام على `organizationContextProvider`. لا يُستخدم السياق إلا عند اختيار فتح مجلس بعينه، ثم ينتقل المستخدم إلى لوحة ذلك المجلس.
- إعادة استخدام المسار الحالي `adminDashboard` دون إنشاء Route جديد.
- إضافة رأس حديث خاص بالمنصة، بطاقة الملف الشخصي، ومبدل اللغة المشترك من المرحلة الأولى.
- إضافة إحصاءات حقيقية فقط:
  - إجمالي المجالس.
  - المجالس النشطة.
  - إجراءات الانضمام المعلقة عند اكتمال قراءة كل المجالس.
- عدم عرض مجموع جزئي على أنه مجموع نهائي إذا تعذر جلب إحصاءات أحد المجالس.
- إضافة إجراءات سريعة مبنية على الشاشات الحالية:
  - إنشاء مجلس.
  - إدارة المجالس.
- إضافة قائمة بحث وبطاقات مجالس متجاوبة للهاتف، تعرض الاسم حسب اللغة، الحالة، تاريخ الإنشاء، وعدد الأعضاء عند توفره.
- إضافة فتح المجلس من البطاقة عبر آلية اختيار المجلس الحالية للمالك الأعلى، ثم الانتقال إلى `councilDashboard`.
- إضافة زر واضح للعودة من لوحة المجلس إلى لوحة إدارة النظام، ولا يظهر إلا للمالك الأعلى للمنصة.
- إضافة تنبيه نظام حقيقي عند وجود طلبات انضمام معلقة، وحالة فارغة عند عدم وجودها.
- دعم العربية RTL والإنجليزية LTR لكل النصوص الجديدة عبر ملفات ARB الحالية.
- إضافة حالات تحميل وخطأ وفراغ بدل الأرقام أو البيانات الوهمية.

## الفصل بين السياقين

- **لوحة إدارة النظام:** تقرأ قائمة المجالس على مستوى المنصة، ولا تراقب المجلس الحالي ولا تعرض الرسوم أو الحجوزات أو الإيصالات الخاصة بمجلس.
- **لوحة المجلس:** تبقى تحت `organizationContextProvider` وتعرض بيانات المجلس المختار فقط.
- اختيار «فتح المجلس» هو نقطة العبور الصريحة الوحيدة: يحدد المجلس أولًا ثم يفتح لوحة المجلس.

## الصلاحيات والحماية

- الدخول إلى واجهة لوحة النظام يتطلب `AdminAccess.isSystemOwner == true`.
- `owner` و`chairman` و`adminManager` وأي مدير محلي لا يحصلون على دخول للوحة النظام بسبب صلاحياتهم داخل مجلس.
- شاشة إنشاء المجلس الحالية تحتفظ بفحص المالك الأعلى الموجود أصلًا.
- لم تتم إضافة عمليات كتابة جديدة أو تجاوزات لقواعد Firestore، ولم تتغير Rules أو Cloud Functions في هذه المرحلة.

## مصادر البيانات

- قائمة المجالس: `OrganizationRepository.streamAllIncludingInactive()`.
- أعداد الأعضاء وطلبات الانضمام: `OrganizationRepository.getOrganizationCounts(organizationId)` لكل مجلس.
- لم تتم إضافة أرقام ثابتة أو بيانات وهمية.

## ما لم يُعرض عمدًا

- **عدد مدراء النظام:** لا يوجد حاليًا مصدر عالمي موثوق ومتاح للقائمة الكاملة، لذلك لم يوضع رقم تقديري.
- **النشاط العام والتدقيق العام:** سجلات التدقيق الحالية موجودة داخل `organizations/{organizationId}/audit_logs` وليست سجلًا عالميًا؛ لذلك لم يُعرض نشاط مختلط أو غير صحيح.
- **إدارة مستخدمين عامة وإعدادات نظام عامة:** لا توجد شاشات إنتاج جاهزة لها ضمن المسارات الحالية، فلم تُنشأ أزرار غير فعالة.
- **جرس الإشعارات في لوحة النظام:** الإشعارات الحالية مرتبطة بالمستخدم/المجلس ولا تمثل صندوق نظام عالميًا موثوقًا، لذلك لم يُعرض كإجراء نظام.
